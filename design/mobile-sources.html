Firecracker cold-start

Asked 11:04 · 6 sources

What changed in Firecracker microVM cold-start performance this year?

The boot number itself barely moved. Firecracker still starts a minimal microVM in roughly a tenth of a second2 — the same order of magnitude as when the design was first published. What changed is that almost nobody is measuring that number anymore.

Restore replaced boot

Restoring a saved microVM skips guest kernel boot and userspace init, so the cost moves to faulting memory back in.13 The userfaultfd handler serves guest pages on demand instead of loading the whole memory file up front,3 so restore scales with the working set rather than the configured memory.

The clock moved too

Our budget doc now measures API accepted to first byte of customer code, not VMM start to kernel handoff.4 On that clock the VMM is a minority of the total — snapshot fetch and network attach dominate.6

On our own fleet, restore p50 has been flat since the UFFD rollout; p99 is the series that still moves.5
