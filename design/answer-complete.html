What changed in Firecracker microVM cold-start performance this year?

6 sources 3 connectors 4.2s · local model

The boot number itself barely moved. Firecracker still starts a minimal microVM in roughly a tenth of a second2 — the same order of magnitude as when the design was first published. What changed this year is that almost nobody is measuring that number anymore. The work went into the paths on either side of it.

Snapshot restore became the normal path

Restoring a saved microVM skips guest kernel boot and userspace init entirely, so the cost moves from booting to faulting memory back in.13 The userfaultfd page-fault handler is the piece that makes that cheap at scale: rather than loading the whole memory file before the VM is allowed to run, the host serves guest pages on demand as they are touched.3 Restore time stops scaling with the guest's configured memory and starts scaling with its working set — which is the actual shift behind most of this year's numbers.

The guest side got the attention

Most of the remaining boot cost was never the VMM; it was the guest probing for hardware a microVM does not have. ACPI support and a trimmed device model let a modern guest kernel skip several of those paths.1 Whether you actually see the win depends on the kernel config you ship, which is why our base image pins its own and tracks it separately.4

And the definition itself changed

Our budget doc was rewritten this quarter around an end-to-end clock — API accepted to first byte out of customer code, rather than VMM start to kernel handoff.4 Under that definition the VMM is a minority of the total; snapshot fetch and network attach dominate. It is the same conclusion AWS reaches for SnapStart, where the optimisation effort sits in restore and pre-warming rather than in boot.6

On our own fleet, weekly restore p50 has been flat since the UFFD rollout; p99 is the series that still moves.5 The chart is in the rail — read those values as this cluster's, not as a general benchmark.

Still unsettled

  • Whether a UFFD restore leaves the host page cache in a state the next restore of the same snapshot can use. Nothing in the index measures this cleanly yet.5
  • Snapshot compatibility across minor versions, which the changelog treats as a per-release question rather than a standing guarantee.1
